## High severity

### 1. Stratified split can silently drop the minority class from the holdout entirely
- **File**: `src/dataset.py:28, 38-44, 76-81`
- **Category**: correctness
- **Finding**: `validate_binary_target` treats `MIN_ROWS_PER_CLASS = 2` rows in the *source* column as sufficient, but `train_test_split(..., stratify=...)` doesn't guarantee a small class lands in *both* resulting splits. It can allocate all of a rare class's rows to train and zero to holdout.
- **Evidence**: reproduced directly - with 998 majority rows and 2 minority rows, the split put both minority rows in train and none in holdout. `classification_report`/`accuracy_score` then run without error and report a plausible-looking number that says nothing about the missing class - the exact "good-looking score that isn't real" failure mode this project exists to catch, originating in the harness's own split logic where neither the modeller nor the critic can see it.
- **Recommendation**: after splitting, assert both classes have non-zero count in *both* train and holdout; raise the same UI-safe `ValueError` if not. A static pre-split row count cannot substitute for checking the actual split output.

### 2. Feature-name normalisation can collide, silently dropping one feature and duplicating another
- **File**: `src/agent.py:250-261` (`_reindex_to_booster_feature_order`, `_normalise_feature_name`)
- **Category**: correctness
- **Finding**: normalisation strips all non-alphanumeric characters and lower-cases, so two columns differing only by case or punctuation (`Age` / `age`, `mean-radius` / `mean_radius`) collide into the same dict key. The last one silently wins, so the booster's feature order gets mapped to the wrong real column and one feature is dropped entirely - no exception, no warning.
- **Evidence**: confirmed empirically with `cols = ['Age', 'age', 'income']` - normalisation collapses `'Age'` and `'age'` to the same key, and the resulting reindex duplicates one column while dropping the other.
- **Why it matters**: this function exists specifically to fix ADR-009's silent-misalignment bug. A real-world uploaded CSV (ADR-007's "any binary-classification CSV" feature) with near-duplicate column names reopens the identical failure mode through a different path.
- **Recommendation**: raise (or hard-warn) if normalisation produces fewer unique keys than `len(X.columns)`, instead of silently overwriting dict entries.

### 3. Corrupted or partially-written JSON crashes the whole dashboard
- **File**: `src/report.py:57-69` (`list_runs`, `load_latest_run`), `src/ui/app.py:336, 192` (calls `list_runs()`/`evaluation.load_latest_summary()` unguarded)
- **Category**: correctness / gap
- **Finding**: every write (`save_run`, `save_rescoring`, `evaluation._save_summary`) is a plain `path.write_text(json.dumps(...))` - not atomic. If the process is killed or a rerun interrupts mid-write (plausible for the evaluation tab's multi-minute blocking call), the file is left truncated. On the read side, none of the JSON loads are wrapped in try/except, and `list_runs()` runs unguarded on *every* sidebar render - so one bad file breaks the entire app until manually deleted.
- **Evidence**: reproduced directly - writing a truncated file into the runs directory and calling `list_runs()` raises an uncaught `json.JSONDecodeError`.
- **Recommendation**: write via temp-file + `os.replace` for atomicity; wrap the JSON reads to skip/report a corrupt file instead of raising.

### 4. Langfuse re-verification is checked off in TODOS.md, but ADR-008 says it was never done
- **Location**: `agent_docs/TODOS.md` (Phase 3), `agent_docs/decisions.md` (ADR-008)
- **Category**: contradiction / todo-accuracy
- **Finding**: TODOS.md marks "Verify Langfuse tracing against the new LiteLLM/Ollama backend" done, but ADR-008 (same date) explicitly states: "Langfuse/observability (ADR-000) has not been re-verified against the LiteLLM/Ollama backend... open follow-up, not assumed to still work." No later ADR records it being verified.
- **Recommendation**: uncheck the TODOS.md item, or actually run and confirm a trace, then update both documents together.

## Medium severity

### 5. `MAX_CALLS_PER_SESSION` check-then-increment isn't atomic under concurrent access
- **File**: `src/services/code_execution.py:43-48`
- **Category**: correctness / resource
- **Finding**: `_call_count` is a plain module-level int, read and incremented as two unsynchronised statements. Streamlit runs each browser session's script in its own thread of one shared process, so two concurrent `run_code()` calls near the ceiling can both pass the check before either increments - the hard ceiling (ADR-003) can be exceeded. Distinct from the already-accepted "budget is process-wide, not per-session" design; this is about the shared ceiling itself not being reliably enforced.
- **Recommendation**: guard the check-and-increment with a `threading.Lock`.

### 6. `_check_foreign_file_path` misreads output-file writes as train/test contamination
- **File**: `src/checks.py:18, 41-46`
- **Category**: correctness
- **Finding**: the regex matches `open(...)` regardless of mode, so a script legitimately writing an auxiliary file (e.g. `open("metrics.json", "w")`) is flagged and reported to the critic as "possible train/test contamination."
- **Evidence**: confirmed - `open("metrics.json", "w")` fails the path-match check and produces a false contamination finding.
- **Recommendation**: only match `open(...)` calls in a read mode, or drop `open` from the pattern and rely on the inherently read-only `read_csv`/`read_json`/`read_parquet` calls.

### 7. A permanently failed training run raises uncaught and leaves no run record
- **File**: `src/agent.py:214-215` (`build_run_report_from_execution`), called from `_run_baseline_async` with no surrounding try/except
- **Category**: gap
- **Finding**: if the modeller exhausts `MAX_TRAINING_ATTEMPTS` still failing, a `RuntimeError` propagates uncaught out of `run_baseline`/`run_baseline_for`. Nothing saves a record for this case - exactly the scenario ADR-008 documents actually happening ("crashed on the same `early_stopping_rounds` bug... repeated runtime errors") - so a real failure mode leaves no JSON trace, unlike every successful run.
- **Recommendation**: catch this in `_run_baseline_async` and persist a failed-run record before re-raising/surfacing to the UI.

### 8. Persisted rescoring history is written but never read back by the UI
- **File**: `src/report.py:92-100` (`list_rescorings`), `src/ui/app.py`
- **Category**: gap / quality
- **Finding**: `save_rescoring` persists each re-score specifically so "past and re-scored verdicts stay comparable" (ADR-010), but `list_rescorings` is never called anywhere in `app.py`. The "Latest re-score result" panel only reads `st.session_state`, populated solely by clicking the button in the *current* session - reopen the app and every previously-saved rescoring is invisible even though it's on disk.
- **Recommendation**: on render, seed the result panel from `list_rescorings(run_id)`'s most recent entry (or show the full history).

### 9. `.env.example` still documents Vertex AI/Gemini setup after Gemini was dropped entirely
- **Location**: `.env.example`, `agent_docs/decisions.md` (ADR-008)
- **Category**: stale-reference
- **Finding**: ADR-008 and CLAUDE.md state Gemini/Vertex AI was removed under a strict "no cloud LLM call, no API key, no cloud fallback" requirement, but `.env.example` still instructs setting `GOOGLE_GENAI_USE_VERTEXAI`/`GOOGLE_CLOUD_PROJECT`/`GOOGLE_CLOUD_LOCATION`. Zero references to these remain in `src/` or `scripts/` (confirmed by grep).
- **Recommendation**: delete the Vertex AI block from `.env.example`; keep the Langfuse keys, which are still genuinely used.

## Low severity

### 10. `docs_mcp_server.get_api_signature` can traverse outside its declared library boundary
- **File**: `src/services/docs_mcp_server.py:45-53`
- **Category**: security
- **Finding**: `library` is checked against a 3-entry allowlist, but the dotted `symbol` path is then resolved via unrestricted `getattr` chaining with no check that each intermediate object still belongs to that library. Since pandas/sklearn import stdlib modules at module scope, `sklearn.os` resolves to the real `os` module - a symbol like `"os.system"` returns that function's real signature/docstring, outside what the tool promises.
- **Note**: not RCE - nothing is called, and inspecting things like `os.environ` returns a class docstring, not live secret values. It's a scope leak, not a credential exposure.
- **Recommendation**: after resolving `obj`, verify `obj.__module__` actually starts with the target library's name before returning anything.

### 11. No cap on artifact size/count read back from the sandbox
- **File**: `src/services/code_execution.py:71-75`
- **Category**: gap
- **Finding**: every file the generated script writes is read fully into memory with no size or count limit - a runaway script could pressure the parent process's memory within the 120s timeout, independent of the already-accepted filesystem/network isolation gap.
- **Recommendation**: cap total artifact bytes read back; log when the cap is hit.

### 12. `_check_val_holdout_gap`'s "last decimal on the line" heuristic is ordering-dependent
- **File**: `src/checks.py:61-80`
- **Category**: quality
- **Finding**: the check assumes the reported accuracy is always the last decimal on its stdout line. A real observed run confirms this ordering holds today, but nothing in the agent's instruction constrains print phrasing - a model writing the value before a threshold would silently extract the wrong number.
- **Recommendation**: not urgent given current evidence supports it; consider matching a labelled pattern (`accuracy[:\s]+(\d\.\d+)`) instead of positional "last decimal."

### 13. Duplicated run/error/rerun scaffolding between the two "Run baseline" buttons
- **File**: `src/ui/app.py:280-289, 312-332`
- **Category**: quality
- **Finding**: the demo-dataset and upload-CSV button handlers are near-identical five-statement blocks (spinner → call → set `selected_run_id` → toast → `st.rerun()`, same try/except), differing only in which function is called.
- **Recommendation**: extract a small `_run_and_display(run_fn)` helper.

### 14. `spike_local_model.py`'s subprocess entry point parses argv positionally with no validation
- **File**: `scripts/spike_local_model.py:146-152`
- **Category**: quality
- **Finding**: the `--trial` subprocess mode reads `sys.argv[2..5]` directly with no argparse or bounds checking - internal-only and safe today, but fragile if the caller and this block drift out of sync. `run_evaluation.py` uses argparse consistently; this script doesn't for this branch.
- **Recommendation**: route through `argparse`, or at minimum assert `len(sys.argv) == 6` with a clear message.

### 15. Phase 1 TODO line still names the superseded stack
- **Location**: `agent_docs/TODOS.md` (Phase 1)
- **Category**: todo-accuracy
- **Finding**: the checked-off item "Confirm tech stack: ADK, gemini-3.7-flash via Vertex AI ADC..." was never updated after ADR-008 superseded the Gemini pick - a reader skimming only TODOS.md gets a wrong picture of the current stack.
- **Recommendation**: low priority given the deadline; append "(superseded by ADR-008)" if convenient.

### 16. Dead cookiecutter template stub files never cleaned up
- **Location**: `src/features.py`, `src/plots.py`, `src/modeling/train.py`, `src/modeling/predict.py`

- **Finding**: four zero-byte files remain from the original scaffold, unimported anywhere in `src/` or `scripts/`.
